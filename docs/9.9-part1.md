# 9.9 第一部分：移除 OpenVINO

本次以文件夹中的 SP25 源码为基线，只完成 `9.9.md` 的第一部分清理。所有保留代码的改动处使用 `[9.9-1]` 注释；已删除文件通过所属 CMake 注释及本文记录用途和原因。

**当前是迁移中间阶段：没有推理后端实现，不生成检测类可执行程序。尚不能运行完整自瞄，也没有树莓派 70–80 FPS 的实测结果。** 第二、三部分接入 HailoRT 和解码后，再恢复相应程序。

## 改了什么、为什么、有什么效果

| 修改位置 | 改动及原因 | 效果 |
| --- | --- | --- |
| 根目录及三个任务目录的 `CMakeLists.txt` | 移除全部 OpenVINO 路径、查找及运行库链接。打符和全向感知原来也带有该依赖，需一起清理 | 工程不再要求安装或链接 OpenVINO |
| `tasks/auto_aim/` | 删除 Classifier、传统 Detector、三个 OpenVINO YOLO 后端、旧后端选择工厂和异步推理链 | 移除旧 CPU/GPU 推理路线及其维护负担，为单一 Hailo 路线留出入口 |
| `tasks/auto_aim/yolo.hpp` | 保留原 `YOLO(config_path, debug)` 和 `detect(img, frame_count)` 声明；删除多后端基类及旧队列专用 `postprocess` | 后续沿用 SP25 调用方式接入 Hailo，不需要重写主处理框架；当前没有空检测或伪推理实现 |
| `tasks/auto_buff/yolo11_buff.*` | 删除推理实现及所有 OpenVINO 成员，仅保留结果结构与调用声明 | 清除打符间接引入的运行库；保留上层打符算法，等待独立模型适配 |
| `tracker.hpp`、`buff_target.hpp` | 分别只依赖 `DetectionResult` 和 `PowerRune` 数据类型，去掉推理器头文件的间接依赖 | 上层算法可独立于检测后端编译，跟踪和预测公式没有变化 |
| `perceptron.hpp` | 删除旧推理线程池 include，直接包含实际使用的标准线程头文件与检测入口 | 清除悬空引用；多相机业务源码保留，尚未承诺其在单块 NPU 上的运行方案 |
| 主程序、检测测试 | 删除旧多线程推理专用入口；保留的 UAV 与测试改用统一 YOLO 入口，移除传统识别分支及命令行选项 | 后续无需维护两条检测路径；标准主循环和 MPC 控制线程保留 |
| 8 份 YAML | 删除旧模型路径、`yolo_name`、CPU/GPU `device`、`classify_model`、`use_traditional`、传统灯条参数及旧打符模型路径；重复 `min_confidence` 只保留一次 | 配置不再指向已删除实现。ROI、相机、通信、标定和上层算法参数保留；Hailo 参数等模型约定确认后再添加 |
| `assets/` | 按引用及 XML 内容确认用途后，删除四组 OpenVINO IR 和旧分类器模型 | 删除模型合计 15,927,574 字节，约 15.2 MiB。这是磁盘空间变化，不代表运行内存或 FPS 的实测改善 |
| `tasks/auto_buff/CMakeLists.txt` | 全仓库源码没有 Ceres 调用或头文件引用，因此同步移除其空的查找与链接 | 少一个实际未使用的构建依赖 |
| `.vscode/c_cpp_properties.json`、`readme.md` | 删除旧 include 路径、依赖安装项及已删除文件条目，标明当前阶段 | 编辑器和使用说明与源码状态一致 |

按 `9.9.md` 继续实现 `tasks/auto_aim/hailo/` 的 HailoRT 运行时与解码，并实现保留的 `YOLO` 入口。HEF 的真实输入/输出、量化参数、颜色/编号/角点约定需先核对，不能仅按文件名假设。自瞄 HEF 的接入不自动恢复打符功能。

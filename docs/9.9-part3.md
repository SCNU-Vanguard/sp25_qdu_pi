# 9.9 第三部分：离线可验证的 Hailo Decoder

第三部分现已实现融合输出到 SP25 `Armor` 的后处理，可以在没有树莓派、HEF、NPU 的电脑上编译测试。**这是在明确模型约定下的代码验证，不代表实际 HEF 已兼容，也不代表完整链路已达到 70–80 FPS。** 所有新增或修改的代码区域用 `[9.9-3]` 标注。

## 改了什么、为什么、有什么效果

| 文件 | 改动及原因 | 效果 |
| --- | --- | --- |
| `tasks/auto_aim/hailo/hailo_decoder.hpp/.cpp` | 新增无 SDK 依赖的 Decoder；读取第二部分已反量化的 `N×22` FLOAT32，集中管理模型语义和过滤参数 | 在电脑上验证后处理；不重复反量化，不影响 HailoRuntime 的内存和设备管理 |
| 同上 | objectness → 类别映射 → 角点映射 → 原图几何 → 有界候选筛选 → NMS → 近重复抑制 → Armor | 低分、错误几何尽早丢弃，减少去重和下游算法的候选量 |
| `tasks/auto_aim/armor.hpp/.cpp` | 提前加入第三部分输出对象必需的语义构造和默认初始化，复用 SP25 原有几何计算 | 不再通过裸颜色/编号猜枚举；避免新检测结果复制、排序时读取未初始化成员 |
| `tasks/auto_aim/CMakeLists.txt`、`tests/hailo/CMakeLists.txt` | 将 Decoder 加入生产 auto_aim；独立测试直接编译同一份 Decoder、Armor、HailoOutput 源码 | 无需安装 HailoRT 即可检查融合到 Armor 的数据链 |
| `tests/hailo_decoder_test.cpp` | 添加合成张量、几何、语义、异常及跨帧测试 | 检测顺序、缩放、去重、未初始化和旧帧残留等错误可在上板前排查 |
| 根 CMake、`yolo.hpp`、README | 更新阶段说明 | 避免把独立后处理实现误认为完整相机自瞄已接通 |

没有修改 Tracker、Solver、Target、Aimer、Shooter、Voter、Planner、相机、通信和标定算法。原有 `Armor` 构造函数的几何计算保留。本轮提前完成了第四部分中必要的语义构造和成员初值；下一部分应基于此继续整理入口，不重复实现。

## 已实现的数据约定

输入列继续按 `9.9.md`：

```text
0..7   四个角点的 x/y
8      objectness
9..12  四种颜色的分数
13..21 九种编号的分数
```

- 默认输入尺寸 640×512，三个尺度、每网格三个候选，与第二部分一致，因此默认严格检查 `20160×22`。尺寸可在构造时指定，必须为 32 的倍数。
- objectness 为 logits 时执行稳定 sigmoid；为概率时不再执行 sigmoid。颜色/编号只做 argmax，单调 sigmoid 不影响其排名，省去逐项 exp。
- **confidence 只取 objectness**，沿用 SP25 的该入口语义，不擅自与类别分数相乘。原 SP25 的 22 列解析、objectness 和角点转换可对照[官方 YOLOV5 实现](https://github.com/TongjiSuperPower/sp_vision_25/blob/main/tasks/auto_aim/yolos/yolov5.cpp)。这些依据不能证明另一份 HEF 的语义相同。
- 输出角点顺序固定为左上、右上、右下、左下，与现有 Solver 的物理点对应。根据显式 `corner_indices` 转换，不按坐标重新排序或通过凸包修补错误顺序。
- 只实现**整图直接 resize** 的逆变换：`x_original = x_input × image_width / input_width`，y 独立计算。尚不接受 ROI、letterbox 填充或输入归一化坐标。
- 丢弃非有限值、超出原图的角点、重复点、近零边、自交、凹四边形、错误绕向和面积过小的候选。不夹紧角点，避免改变 PnP 使用的几何。边缘不完整装甲会被过滤，这是当前有意采用的策略。
- `not_armor` 被过滤；四个颜色保留，由后续 SP25 Tracker 决定敌我。映射要求是四个 Color、九个 ArmorName 和四个角点索引的排列，缺失/重复映射在构造时拒绝。若真实模型有合并类别或不同标签含义，需据真实导出修改此约定。

## 尚未确认的 HEF 语义

`HailoDecoderContract` 没有可直接用于目标模型的默认类别映射，`corners_are_input_pixels` 默认为 false。调用方必须提供映射，并确认角点已经是网络输入像素，才能构造 Decoder。

**不能仅为让构造通过而把这个字段改成 true。** 如果目标 HEF 的角点是 raw grid/anchor 编码，还必须先根据该 HEF 对应的导出/后处理源码实现准确的坐标公式。当前没有添加猜测的 anchors、stride 解码、归一化坐标或坐标 sigmoid。

测试夹具显式约定颜色 `[blue, red, extinguish, purple]`，编号 `[sentry, one, two, three, four, five, outpost, base, not_armor]`，原始角点 `[LT, LB, RB, RT]`。**它们只是可核算的测试输入，不是 `szu_int16_head_l.hef` 的已验证配置。** 生产 YAML 和 YOLO 尚未写入这些映射。

回到树莓派后仍需：

1. 记录同一份 HEF 的 SHA256，执行 `hailortcli parse-hef`，核对第二部分的输入、输出和量化信息。
2. 找到同一份 HEF 的预处理/导出/后处理源码，确认 RGB、归一化、类别顺序、角点通道排列、坐标公式、分数是否已有 sigmoid。
3. 对照一张装甲图片的真实结果，必要时修正第二部分布局和第三部分坐标/类别约定，再将 runtime、前处理和 Decoder 接入 YOLO。
4. 运行 Pi 设备测试，然后按后续阶段测完整链路帧率和长稳。现有 `hailo_runtime_test` 仍只测原始推理与融合，不自动调用这个未核对的 Decoder。

## 参数与性能边界

| 参数 | 当前初值 | 含义 |
| --- | --- | --- |
| `min_confidence` | 0.8 | objectness 阈值，等于阈值保留；与现有配置初值一致 |
| `nms_iou` | 0.5 | 跨类别 bbox IoU 大于此值时，只留更高分者，延续原 SP25 的 NMS 策略 |
| `min_quad_area` | 4 | 原图四边形最小面积，单位 px² |
| `duplicate_center_ratio` | 0.15 | 同颜色、同编号的中心距离不大于较小灯条平均长度的此比例时去重；0 关闭 |
| `big_armor_ratio` | 3.2 | 使用原图角点的最大上下边长/最大左右边长，判别 3/4/5 和基地大小；英雄大、工程/哨兵/前哨小 |
| `max_candidates` | 256 | 进入 NMS 的最高分候选上限 |
| `max_detections` | 128 | 最终 Armor 数量上限 |

大小板判别和过滤阈值是可调整的开发初值。图像透视会影响宽高比，需用实际画面校准，不能把这个阈值当成真实物理尺寸的保证。

候选采用固定上限的堆，遍历全部行后保留最高分 K 个，避免简单截断前 K 行而漏掉后面检测尺度的高分目标。同分按融合行号决定取舍，结果可重复。候选、保留索引缓冲在构造时 reserve，帧间 clear 复用；只有筛选后的 Armor/list/角点容器需要生成，不声称整条路径零分配。

Decoder 同一实例仅用于一个处理线程；返回的 Armor 独立拥有角点，不引用下一帧会被覆盖的融合/候选缓冲。默认优先级为 `fifth`，是确定初值，不是新增的兵种优先级策略。位姿零初值表示尚未解算，不是有效测量。

## 本地验证与重现

独立测试需要 OpenCV 和 Eigen，不需要 HailoRT、模型、相机或 NPU。在 Linux/WSL 工程根目录：

```bash
cmake -S tests/hailo -B build/hailo-tests -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS='-fsanitize=address,undefined -fno-omit-frame-pointer' \
  -DCMAKE_EXE_LINKER_FLAGS='-fsanitize=address,undefined'
cmake --build build/hailo-tests -j2
ctest --test-dir build/hailo-tests --output-on-failure
```

测试覆盖 4×9 类别映射、大小板、logits/概率、阈值边界、非等比缩放、倾斜角点/PnP 顺序、默认成员、非法几何/NaN/Inf、跨类别 NMS、同类近重复、跨尺度 top-K、稠密 20160 行、非连续 Mat、融合到 Armor 和 100 帧结果生命周期。

本轮在 WSL Ubuntu 22.04 / GCC 11.4 / OpenCV 4.5.4 下构建成功，启用上述两种 sanitizer，CTest **2/2 通过**。新增 Decoder 和测试源码额外通过 `-Wall -Wextra -Wpedantic` 编译检查；7 个上层算法源码也通过使用新 Armor 头文件的编译兼容检查。

已清理本轮编译对象、测试二进制和 CMake 缓存共 **19,019,116 字节**，仅保留小型记录 `build/part3-validation/results.md` 和可重现的测试源码。没有在本机安装新依赖或恢复 OpenVINO；Pi 链接、真实 HEF 识别与 70–80 FPS 尚未验证。

### 完整数据流程

1. 相机或读图提供 BGR、8 位、3 通道图像。`YOLO` 检查输入类型，直接 resize 至 640×512，再转 RGB；不做 letterbox 填边，不除以 255，与参考 `BuildNetworkInput` 相符。
2. `HailoRuntime` 只加载一次 HEF。沿用原生 UINT16/UINT8 输出及固定 NHWC 主机布局，按各流量化参数执行 `(整数值 - zero_point) × scale`。这叫**反量化**，把模型压缩存储的整数转换回后处理需要的实数。
3. 新模型模块执行参考 `FuseOneHailoOutput` 的 **tail**（留在 CPU 上的模型末段计算）。先把 22 项舍入到 FP16 再转回 FLOAT32，与参考 ARM 路径一致；随后仅对前 8 项做角点换算：

   ```text
   pixel_x = rounded_raw_x × anchor_width  + grid_x × stride
   pixel_y = rounded_raw_y × anchor_height + grid_y × stride
   ```

   anchor 是这组候选采用的宽高尺度，grid 是网格位置，stride 是相邻格在输入图上相差的像素。三个尺度分别使用：

   | stride | 三组 anchor（宽、高） |
   | --- | --- |
   | 8 | (10,13)、(16,30)、(33,23) |
   | 16 | (30,61)、(62,45)、(59,119) |
   | 32 | (116,90)、(156,198)、(373,326) |

   输出行重排为“尺度 → anchor → y → x”，对齐参考函数每个 head 内的次序。该步骤额外复用一块约 1.69 MiB 的 FLOAT32 张量，不在每帧创建模型或积压历史输出。
4. `Decoder` 对第 8 项执行一次 sigmoid，得到 0–1 置信度。参考字段虽然名为 `confidence_is_logit=false`，但其 `decode_confidence` 的 false 分支实际执行 sigmoid；这里依据函数实现，不根据字段名猜测。类别仍按原始分数取最大项，不乘到置信度上。
5. 原始颜色 0→蓝、1→红、2/3→丢弃；原始编号 0→哨兵、1–5→同号、6→前哨、7/8→基地。角点按 `{0,3,2,1}` 变为 SP25 的左上、右上、右下、左下，然后分别乘原图宽/640、高/512，还原至原图坐标。
6. 沿用前几部分的置信度阈值、几何校验、有界候选、NMS、近中心重复抑制和 Armor 初始化。NMS 指“同一装甲出现多个重叠候选时，保留较可信的结果”。返回的 Armor 独立拥有四点，不会随下一帧覆盖而改变。

保留 SP25 已实现的筛选/大小板启发式，没有复制青大整套候选过滤；因此不是声称两个项目最终检出集合完全一致。初始置信度 0.8、NMS 0.5 与大小板阈值仍须实图检验。参考代码的多量化参数分支按 field 0–21 索引；SP25 沿用 HailoOutput 对完整 66 通道分别索引的实现。实际 HEF 后续已确认三路各只有一组量化参数，实测值见第 11 节。

YOLO 启动时核对输入名、三个输出名/尺寸/类型，拒绝明显不匹配的模型；这不是文件 SHA-256 校验。更换 HEF 时仍应先核对上面的指纹，不能仅改文件名复用此适配。

## 10. 真实运行发现的 batch 配置冲突

[09-12 用户终端实测] 首次运行 `hailo_runtime_test` 时，SDK 报告网络组和网络同时指定 batch size，程序输出 `configure network group failed (6): HAILO_INVALID_OPERATION`。从生产调用顺序可知，图片读取、HEF 元数据检查和设备创建已通过，失败发生在 `device->configure()`，数据流尚未建立、推理尚未开始。

原因是此前 `hailo_runtime.cpp` 同时设置组层 `entry.second.batch_size = 1` 和网络层 `network_params.second.batch_size = 1`。即使数值相同，[HailoRT 4.24.0 官方参数说明](https://github.com/hailo-ai/hailort/blob/v4.24.0/hailort/libhailort/include/hailo/hailort.h#L1434) 也要求两层只选一层指定；这不是模型识别错误或软件版本不匹配。

本次仅修改生产文件 `tasks/auto_aim/hailo/hailo_runtime.cpp`，标注 `[Pi-batch]`：组层设为 `HAILO_DEFAULT_BATCH_SIZE`，网络层保留显式 `1`。该宏的值 0 是 SDK 默认配置标记，不表示网络处理零帧；本网络仍以 1 帧为一批。设备数、调度模式、队列、模型、前后处理和 SP25 上层框架均未修改。此前 5 项基础测试不调用真实 SDK 配置流程，不能覆盖该错误；后续 Pi 已实际通过网络配置和推理，见第 11 节。

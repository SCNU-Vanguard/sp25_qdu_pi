## 为什么通信监视入口要改

旧 standard3 的 tx_enabled=false，而原 pi_standard3_qdu 的 tx_enabled=true。只替换 YAML 而不检查消费者，会让普通监视命令因发送开关不匹配而失败，还可能启动真车配置的中性帧发送路径。
因此接收监视入口显式使用已有的 CBoard 强制只读能力，不改变生产通信实现。显式发送的原回归测试仍保留。

## 同步到树莓派

电脑 PowerShell：进入项目，上传完整包。它来自一个电脑 Git 提交，不包含用户照片、日志、Git 历史或自动备份。

```powershell
cd D:\workspace\sp_vision_25-main
scp .\build\pi-sync\sp25-main-source.tar.gz xiao@192.168.1.105:~/
```

树莓派 SSH：先停止当前相机/通信程序。解压不会自动删除旧文件，因此本次增加明确的旧配置清理步骤。
remove_retired_configs.py 仅处理上表五个旧路径，内容必须匹配电脑 Git 中已知历史版本；它先检查全部候选再删除。只要发现陌生修改就保留所有候选并停止，不自动备份，也不删除其他文件。不存在的旧文件跳过，可重复运行。
verify_source.py 随后检查新主源码一致性。编译的是已有程序，最后删除传输压缩包；任何一步失败停止后续步骤。

```bash
(
  set -e
  cd ~/sp_vision_25-main
  tar -xzf ~/sp25-main-source.tar.gz
  python3 build/pi-sync/remove_retired_configs.py --apply
  python3 build/pi-sync/verify_source.py
  cmake --build build/pi-standard --target standard standard_readonly cboard_test capture calibrate_camera -j4
  cmake --build build/pi-communication --target qdu_link_monitor -j4
  rm -- ~/sp25-main-source.tar.gz
)
```

已存在的独立 Hailo 测试构建目录（例如 build/pi-hailo）也应在下次使用前重新编译 hailo_camera_test，以更新其默认路径；历史可执行文件不会因为源码同步自动改变默认值。不要求现在启动硬件测试或重新建额外构建目录。

## 更新后的常用命令

以下均从树莓派 `~/sp_vision_25-main` 执行，每次只运行一个占用相同设备的程序。


真车 standard 入口同样读取 configs/standard3.yaml，具备发送能力；本次同步和编译不自动运行它，后续按真实电控联调步骤使用。

回退通过电脑 Git 恢复对应版本后重新导出完整包。不要仅恢复 YAML 而遗漏程序默认路径和监视工具的配套修改。

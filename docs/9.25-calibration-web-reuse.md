# 2026-09-25：复用 SP25 原标定程序，支持 SSH + 浏览器

## 改动范围

复用原有标定入口，没有引入青大的框架，没有更改 CMake 或正式识别配置；后续加入共用圆点检测函数和实拍板配置修正。

- `calibration/capture.cpp`：保留相机驱动、圆点检测、原图保存、原来的窗口/四元数采集；增加 `--camera-only`、`--preview-port`、`--board-config`。
- `calibration/calibrate_camera.cpp`：增加 `--no-display`，保留 `findCirclesGrid`、`calibrateCamera(CALIB_FIX_K3)`、原来的误差计算和 YAML 输出。
- `tests/live_preview.hpp`：复用现有 HTTP/JPEG 预览，允许采图程序提供自己的页面说明；原调用方式仍有效。
- `calibration/circle_grid.hpp`：采图、求解共用的圆点检测，原方法失败后才尝试暗部阈值与透视检测。
- `configs/calibration.yaml`：HC7-300-15 的板参数与标定采图相机设置。

采图从标定配置读取圆点列数和行数，取代原来写死的 10×7；当前仍只支持横竖对齐的对称圆点板。
`--camera-only` 不构造 CBoard，不保存四元数。其他模式的 CBoard 使用已有的强制只读选项，并在保存时检查 IMU 是否新鲜。
输出文件夹必须为空，避免从 `1.jpg` 开始覆盖旧照片。求解拒绝混合尺寸、非法板尺寸和不足三张有效照片；三张仅是最低计算门槛，不是质量验收标准。

本次未修改用户已有的 `src/standard_readonly.cpp`、`tests/communication/qdu_link_monitor.cpp` 和 `pics/`。

## 本地验证

在 WSL Ubuntu 22.04 / OpenCV 4.5.4 编译原求解入口和替身相机采图入口，清除 DISPLAY / WAYLAND_DISPLAY 后检查：

- 20 个不同姿态的合成圆点视角，设定焦距 850 / 855 px，解得约 849.87 / 854.87 px。
- 网页及 JPEG 接口可访问；页面显示正确的标定说明和 found/saved 状态。
- SSH 标准输入 s / q 可保存和退出；保存图片保持 720×540 且没有检测覆盖层。
- camera-only 不调用 CBoard 构造，不生成假四元数文件。
- 无有效板时拒绝保存，非空目录拒绝覆盖；无照片及混合尺寸输入清晰报错。

这是软件验证；树莓派 ARM 构建、海康真机取图、实际板检测和标定质量仍需上板验证。
验证脚本与生成文件放在忽略的 `build/calibration-reuse-check/`，不加入生产源码。

### 真机首帧超时修复

真机报告 `HikRobot read timeout; use read_frame() for recoverable reads`。
原采图入口沿用了 `camera.read()`，一次等待超时便抛异常退出。
改用项目已有的 `read_frame()`，无帧时继续等待并每秒最多提示一次，重连仍由原相机驱动负责。
持有帧引用直至本轮预览和保存结束，确保图像内存有效；无帧时按 s 不保存旧图，按 q 回车或 Ctrl+C 可以退出。
替身相机覆盖启动时无帧、运行中短暂无帧以及持续无帧退出；这些验证不等同于真机已经恢复取图。

### 暗部和倾斜检测修正

用户反馈慢速移动和倾斜时也容易丢失，单纯调整曝光尚未满足实际使用。
共用函数先调用原来的 `findCirclesGrid`，成功时直接使用原结果；失败时采用 OpenCV 自带的 `SimpleBlobDetector`，将 minThreshold 从默认 50 改为 5、thresholdStep 从默认 10 改为 5，再调用 `SYMMETRIC_GRID | CLUSTERING`。
其他面积、颜色、形状筛选保留默认值，不改标定求解器。按[OpenCV 文档](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)，CLUSTERING 对透视更稳，但对杂乱背景更敏感，因此仅作为回退路径。
每次只处理当前原图；没有时间平滑或旧圆心保留，失败时清空输出，仍要求完整阵列才允许保存。

临时几何回归程序已按用户要求移到忽略的 `build/calibration-reuse-check/circle_grid_test.cpp`，不留在主源码中，也不传到树莓派：48 张不同倾斜、亮度、模糊的合成板图，原方法通过 27/48，新方法 48/48；最大圆心位置误差约 0.518 px。
缺一个圆点的板、纯色画面和用户采集的 12 张无板图片均拒绝。之前的暗截图在相同回退参数下可检出 49 个圆心。
这些数据是本地软件验证，不是实测成功率；真机运动、反光、离焦或严重倾斜仍需验证。
独立编译运行方式：

```bash
g++ -std=c++17 -O2 -I. build/calibration-reuse-check/circle_grid_test.cpp \
  $(pkg-config --cflags --libs opencv4) -o build/circle_grid_test
./build/circle_grid_test
```

## 同步：电脑端 Git 管理，树莓派只编译运行

树莓派不再自动生成源码备份目录或备份压缩包；同步临时文件在成功使用后删除。
源码以电脑上的提交为准，正式修改在电脑提交后同步；树莓派现场调试改变的配置，应先回传电脑核对并提交，再进行下次同步。
为保证主代码一致，后续使用完整主源码包，不再只同步标定的几个文件。打包内容来自同一个 Git 提交：`calibration/`、`configs/`、`io/`、`src/`、`tasks/`、`tests/`、`tools/` 中的受管理文件，以及根目录 CMake/运行辅助文件、已跟踪的运行资源。
不包含 Git 历史、Markdown 文档、build 产物、日志、用户图片和标定照片。原项目已有测试入口和实际调用的 `tests/live_preview.hpp` 保留；本次临时回归源码不保留在主目录。
压缩包内的 `build/pi-sync/` 只放版本清单和校验工具，允许两边不一致的辅助文件集中放在 build 下。

Windows PowerShell（将地址替换为当前能 SSH 登录的树莓派 IP）：


树莓派 SSH：先停止当前相机程序。下面整段在子 shell 中执行，失败会停止，不会退出 SSH。解压主源码后先校验，再编译；成功后删除传输包。

这是完整主源码同步，包含所有已跟踪配置及工程使用的海康 SDK 文件，不包含外部 `workspace/current` 的 HEF 模型。
校验会核对清单内文件内容，并报告源码目录中额外的源文件；不会自动删除不明文件。若提示差异，先检查差异再处理，不能仅凭解压成功宣称一致。
Git 导出的文本采用提交中的行尾；电脑编辑器工作副本可能使用 CRLF，这不属于代码内容差异。

## 板参数与采图

### 实拍板修正（pics/image_11.png）

截图中的板是对称 7×7 圆点，配置旧值 10×7 不匹配；截图画面明显偏暗。
取截图内的相机区域恢复至 720×540 做离线对照：7×7 在原亮度下失败，在两倍亮度下检测到 49 个圆心；10×7 均失败。
这是截图诊断，不代替真机原图验证。检测代码保持不变。
现有 `configs/calibration.yaml` 改为 7×7，采图曝光由 3 ms 改为 6 ms，并显式匹配正式程序的相机串号、720×540、2×下采样、180°旋转和自由运行模式。
用户后续确认型号为 DFvision HC7-300-15；根据[厂家圆点板规格表](https://dfstore.net/products/circular-dot-calibration-board)中 HC7-300-15 行，板尺寸为 300×300 mm、圆直径为 15 mm、圆心间距为 30 mm、阵列为 7×7。`center_distance_mm` 已由待确认的 0 更新为 30，型号中的 15 不是圆心间距。
规格表图片：https://cdn.shopify.com/s/files/1/0804/4678/3511/files/ydbdb.jpg?v=1784291549 。圆心间距只用于生成三维标定点，不参与采图时的 yes/no 判断，因此此更新不等同于解决识别不稳定。
正式识别使用的 `configs/pi_standard3_qdu.yaml` 不变。
电脑端提交后，单独上传 `configs/calibration.yaml`；源码无需再次编译。

先检查 `configs/calibration.yaml` 的前三项：

```bash
sed -n '1,3p' configs/calibration.yaml
```

`pattern_cols` 是圆点列数，`pattern_rows` 是行数，`center_distance_mm` 是相邻圆心距离（不是圆的直径）。
当前行列为照片已核对的 7、7，圆心间距为厂家 HC7-300-15 规格表给出的 30 mm。错行排列的圆点板不能直接用当前的对称圆点求解。
如需修改参数，在电脑端编辑并单独提交 `configs/calibration.yaml`，再上传。若树莓派该配置曾有现场修改，先回传比较，避免覆盖现场参数。

## 求解与填写结果

在同一个 SSH 终端继续执行（新终端需要把 calib_dir 重新设为刚才实际保存目录）：

```bash
./build/pi-standard/calibrate_camera "$calib_dir" \
  --config-path=configs/calibration.yaml --no-display
```

它逐张打印检测成功/失败，最后打印重投影误差与 `camera_matrix`、`distort_coeffs` 两行。
先检查有效视角数量、误差和数值，再把两行替换到 `configs/pi_standard3_qdu.yaml` 同名项。
这两个参数描述本次相机成像；不要改 `R_camera2gimbal`、`t_camera2gimbal`、`R_gimbal2imubody`，那些是后面的外参/坐标系项目。
采用当前原图几何求出的结果不需要再次做 2 倍缩放或 180° 转换。换镜头、焦距、分辨率、裁剪或旋转设置后要重新核对标定。

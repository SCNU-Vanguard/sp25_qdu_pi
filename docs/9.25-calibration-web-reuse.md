## 改动范围

复用原有标定入口，没有引入青大的框架，没有更改 CMake 或正式识别配置；后续加入共用圆点检测函数和实拍板配置修正。

- `calibration/capture.cpp`：保留相机驱动、圆点检测、原图保存、原来的窗口/四元数采集；增加 `--camera-only`、`--preview-port`、`--board-config`。
- `calibration/calibrate_camera.cpp`：增加 `--no-display`，保留 `findCirclesGrid`、`calibrateCamera(CALIB_FIX_K3)`、原来的误差计算和 YAML 输出。
- `tests/live_preview.hpp`：复用现有 HTTP/JPEG 预览，允许采图程序提供自己的页面说明；原调用方式仍有效。
- `calibration/circle_grid.hpp`：采图、求解共用的圆点检测，原方法失败后才尝试暗部阈值与透视检测；另提供只影响显示的横向连线。
- `configs/calibration.yaml`：HC7-300-15 的板参数与标定采图相机设置。

采图从标定配置读取圆点列数和行数，取代原来写死的 10×7；当前仍只支持横竖对齐的对称圆点板。
`--camera-only` 不构造 CBoard，不保存四元数。其他模式的 CBoard 使用已有的强制只读选项，并在保存时检查 IMU 是否新鲜。
输出文件夹必须为空，避免从 `1.jpg` 开始覆盖旧照片。求解拒绝混合尺寸、非法板尺寸和不足三张有效照片；三张仅是最低计算门槛，不是质量验收标准。

本次未修改用户已有的 `src/standard_readonly.cpp`、`tests/communication/qdu_link_monitor.cpp` 和 `pics/`。

### 真机首帧超时修复

真机报告 `HikRobot read timeout; use read_frame() for recoverable reads`。
原采图入口沿用了 `camera.read()`，一次等待超时便抛异常退出。
改用项目已有的 `read_frame()`，无帧时继续等待并每秒最多提示一次，重连仍由原相机驱动负责。
持有帧引用直至本轮预览和保存结束，确保图像内存有效；无帧时按 s 不保存旧图，按 q 或 Ctrl+C 可以退出。
替身相机覆盖启动时无帧、运行中短暂无帧以及持续无帧退出；这些验证不等同于真机已经恢复取图。

### SSH 单键保存

用户要求直接按 s 保存，不再需要回车。`capture.cpp` 在网页预览且标准输入为真实终端时，临时关闭终端的行缓冲与按键回显，保留 Ctrl+C 的信号功能；q 退出、Ctrl+C 退出以及异常返回时恢复原终端设置。
使用小型局部 TerminalInput 类管理恢复，不新增生产文件、读键线程或外部依赖；管道输入与原 OpenCV 窗口模式继续使用原有路径。
先选中正在运行采图程序的 SSH 终端，再短按 s 保存、短按 q 退出，不用回车；浏览器页面只用于看画面。按 s 仍要求当前帧有效，camera-only 模式仍要求完整圆点阵列。无帧或无板时明确提示没有保存，不会把旧帧充作新照片。
网页说明和终端说明同步更新；检测、横向连线、曝光与照片格式均未更改。

临时验证仅放在忽略的 build 下，用 Linux 伪终端运行真实采图入口和替身相机，检查不含换行的 s 保存、q 退出、终端 Ctrl+C、异常退出、无帧/无板拒绝保存、终端属性恢复，以及非终端输入兼容。实际树莓派仍需同步编译后验证。

### 暗部和倾斜检测修正

用户反馈慢速移动和倾斜时也容易丢失，单纯调整曝光尚未满足实际使用。
共用函数先调用原来的 `findCirclesGrid`，成功时直接使用原结果；失败时采用 OpenCV 自带的 `SimpleBlobDetector`，将 minThreshold 从默认 50 改为 5、thresholdStep 从默认 10 改为 5，再调用 `SYMMETRIC_GRID | CLUSTERING`。
其他面积、颜色、形状筛选保留默认值，不改标定求解器。按[OpenCV 文档](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)，CLUSTERING 对透视更稳，但对杂乱背景更敏感，因此仅作为回退路径。
每次只处理当前原图；没有时间平滑或旧圆心保留，失败时清空输出，仍要求完整阵列才允许保存。

临时几何回归程序已按用户要求移到忽略的 `build/calibration-reuse-check/circle_grid_test.cpp`，不留在主源码中，也不传到树莓派：48 张不同倾斜、亮度、模糊的合成板图，原方法通过 27/48，新方法 48/48；最大圆心位置误差约 0.518 px。
缺一个圆点的板、纯色画面和用户采集的 12 张无板图片均拒绝。之前的暗截图在相同回退参数下可检出 49 个圆心。
这些数据是本地软件验证，不是实测成功率；真机运动、反光、离焦或严重倾斜仍需验证。
独立编译运行方式：

```bash
g++ -std=c++17 -O2 -I. build/calibration-reuse-check/circle_grid_test.cpp \
  $(pkg-config --cflags --libs opencv4) -o build/circle_grid_test
./build/circle_grid_test
```

### 横向连线与标定结果的关系

用户确认当前实板检测效果良好，本次保留 `find_circle_grid` 的检测代码和所有配置不变。
按用户最新要求恢复原 OpenCV `drawChessboardCorners` 的彩色圆心标记与原有连线，包括它自身的跨行连接。仅在绘图前把圆心副本排成更接近画面水平的行，并统一每行从左往右、各行从上到下的顺序。检测器的行列交换、起点反转不会再仅因返回顺序改变而导致显示颜色和连接方向切换。
线仍穿过真实检测到的圆心，所以会随板倾斜；板在画面内转到两组方向同样接近水平（通常约 45°）附近时，仍存在选哪一组的临界点。本改动不保证跟踪同一条物理行，也不把斜板画成水平板。

7×7 对称阵列转过 90° 仍然是同样的几何图案，单靠圆点无法唯一认定物理起点与行方向。原 `drawChessboardCorners` 按检测返回顺序连接，因此行列互换就可能看到横竖切换。新绘图只读取圆心，在图像副本上画线；保存的原图和传给求解器的圆心数组不变。

对当前单目内参标定，完整规则方阵的整体 90°/180° 旋转或行列交换可以由各照片分别求解的板姿态吸收，不等于内参出错；错连邻居、漏点、混入背景点等非整体规则变换不能这样解释。
后续若要比较板姿态或做手眼标定，就需要跨照片一致的物理板坐标系。仅固定显示横线没有解决这个问题，不能据此宣称手眼数据有效。

本地验证覆盖三个倾斜方向、各八种整体返回顺序：24 种结果与统一方向后直接调用原 OpenCV 绘图逐像素相同，不改变输入圆心和原图；失败或圆心不全时不绘制。采图入口与求解入口在 WSL 编译通过。临时验证文件仅在忽略的 build 中，不随主源码交付。

### 为什么初次迁移表现较差、后来改善

这里的对照基线是本仓库加网页前的提交 `936fd18`，它已经包含部分树莓派适配；不是声称拿到了用户过去成功运行时的完整原始 SP25 环境。

| 文件 | 基线行为 | 现在的变化与用途 |
| --- | --- | --- |
| `calibration/capture.cpp` | 固定找 10×7；依赖本地 OpenCV 窗口和 C 板；单次读帧超时退出 | 从配置读板尺寸；可浏览器预览、SSH 按键；camera-only 不依赖 C 板；复用驱动 read_frame 容忍短暂无帧；仍由 s 保存原图 |
| `calibration/calibrate_camera.cpp` | 读取照片、检测圆点、calibrateCamera 求内参、窗口逐张显示 | 保留求解器、CALIB_FIX_K3、误差计算与 YAML 输出；共用增强检测、可不显示窗口，检查输入尺寸和有效照片数 |
| `calibration/circle_grid.hpp` | 无此文件，检测各入口直接调用 OpenCV | 两个入口共用小函数，先原方法、失败再增强；此次加横向绘图，不改检测 |
| `tests/live_preview.hpp` | 已有项目网页预览工具 | 复用它展示标定画面，只增加可配置提示文字等小调整；不是新造网页框架 |
| `configs/calibration.yaml` | 旧板 10×7、间距 40 mm、曝光 3 ms | 实板 7×7、间距 30 mm、曝光 6 ms；显式匹配正式链路 720×540、2 倍下采样、旋转 180° 等成像设置 |

最初配置与实板不匹配，之后暗图和倾斜仍使原默认检测易失败。曝光调整帮助采图，但运动时仍应摆稳，曝光增加也会增加拖影机会。最近明显改善对应的是暗阈值与透视回退检测：更完整地找出当前图像里的圆点，不是沿用上一帧把线“锁住”。圆心间距修正只影响三维板模型，不改善 yes/no 检测。

浏览器仅接收加标记的预览副本，JPEG 编码在检测之后；压缩的网页图不会送回检测或保存。不能把这次问题直接归因于网页压缩或移除 OpenCV 窗口，原窗口模式也保留了。
树莓派适配主要解决无桌面的显示/按键、相机帧接口、运行图像几何一致和内参采集不依赖 C 板。圆点检测与内参求解运行在 CPU 的 OpenCV 上，本流程没有调用 Hailo 装甲板模型；暗部和倾斜检测改进同样可用于电脑。

整体流程：海康相机原图 → 找完整圆心阵列 → 副本画线并发给浏览器；按 s 时保存原图 → 离线重新检测圆心 → 原 SP25 求解器 → camera_matrix / distort_coeffs。

### 建议本次采 30 张，分组摆板

相机保持固定，镜头先调清晰，采集中不再拧动镜头。保持同样的 720×540、下采样和图像旋转。移动的是标定板；每张都让全部 49 个圆点和周围白边完整入镜，避免反光和遮挡。先停稳约一秒再短按 s，看到 Saved 和计数增加后才移动到下一姿态；不要长按 s 或在同一姿态连拍。

| 张数 | 怎么摆 |
| --- | --- |
| 1–6 | 画面中央，改变远近，让圆点阵列在图中呈现几种明显不同的大小，加入轻微倾斜；不要让远处圆点小到模糊 |
| 7–14 | 左上、右上、左下、右下各两张，靠近边缘但不裁掉圆点和白边 |
| 15–22 | 板左侧靠近相机、右侧靠近、上边靠近、下边靠近，各两种角度；大约 10–30° 起步，不必强求特别斜 |
| 23–30 | 把上述倾斜分布到不同位置与距离，补足覆盖，避免重复前面的同一姿态 |

数量是本次采集建议，不是自动合格标准。OpenCV 官方教程强调需要不同位置的多张清晰照片，重复姿态提供的信息有限：https://docs.opencv.org/4.x/d4/d94/tutorial_camera_calibration.html 。
尽量一次采完再按 q，因为当前 capture 不向非空目录追加，重新启动会要求新目录。已有旧照片不会被新建目录覆盖，也不需要因本次显示样式修改重拍原本合格的照片。

## 求解与填写结果

采完按 q 退出，在同一个 SSH 终端继续执行。以下命令不再开相机，只读取照片；同时把终端输出保存到本次照片目录的 `calibration-result.txt`。重复计算会覆盖该目录同名结果文件，不覆盖 jpg。
`test` 两行检查目录变量已经设置、目录存在；`set -e` 使检查失败即停止，`pipefail` 保留求解失败状态，防止 tee 写文件成功掩盖了求解失败。括号使这些设置不影响 SSH 后续操作。

```bash
(
  set -e
  set -o pipefail
  cd ~/sp_vision_25-main
  test -n "$calib_dir"
  test -d "$calib_dir"
  ./build/pi-standard/calibrate_camera "$calib_dir" \
    --config-path=configs/calibration.yaml --no-display \
    2>&1 | tee "$calib_dir/calibration-result.txt"
)
```

`--config-path` 指定板尺寸参数，`--no-display` 不开本地窗口，`2>&1` 把错误输出一起收集，`tee` 同时显示并写入结果文件。结果和照片放在同一个目录，不需要到处建备份。
如果换过 SSH 终端，原来的变量会丢失：先用 `ls ~/sp_vision_25-main/assets/img_with_q/` 查看目录名，然后把 `calib_dir` 设成想计算的那个实际目录（不能重新用 date 生成一个没有照片的新目录）。

它逐张打印 `[success]` / `[failure]`，最后打印重投影误差与 `camera_matrix`、`distort_coeffs` 两行。因为原读取逻辑按编号逐张尝试，最后找不到下一张可能出现一次 imread 警告；如果 1 到最后一张完整处理，随后正常输出参数，那不是前面照片丢失。但中间编号缺口会提前停止，必须检查。
用 `cat "$calib_dir/calibration-result.txt"` 可以重新查看结果；用 `grep -c '^\[success\]' "$calib_dir/calibration-result.txt"` 可以统计有效照片数。建议本次 30 张中至少有 20 张清晰、不同姿态的有效视角，再结合误差与独立距离/投影检查评估，不能只满足程序最低三张条件。
程序当前打印的是各点的平均像素距离误差，不是 RMS；数值越小表示与这些照片拟合越好，但低误差不能单独证明实物测距准确。先把完整结果文件发来检查，再采用参数。

结果文件是记录；正式运行程序不会自动读取它。确认后，在电脑端 `configs/standard3.yaml` 替换 `camera_matrix` 和 `distort_coeffs` 两个已有项（不要重复追加同名项），不是填回 `configs/calibration.yaml`。
这两个参数描述本次相机成像；不要改 `R_camera2gimbal`、`t_camera2gimbal`、`R_gimbal2imubody`，那些是后面的外参/坐标系项目。
采用当前原图几何求出的结果不需要再次做 2 倍缩放或 180° 转换。换镜头、焦距、分辨率、裁剪或旋转设置后要重新核对标定。

配置修改同样在电脑端单独提交、重新打包并同步；提交说明记录照片目录、尺寸和误差，删除同处已经失效的“临时估算内参”注释。只修改 YAML 参数不需要重编 C++，但必须重启识别程序才会重新读取。
软件输出结果不代表已经通过实际几何/跟踪验收；回到只读识别链路检查位置、距离与模型投影，然后继续外参、姿态和通信发送验证。

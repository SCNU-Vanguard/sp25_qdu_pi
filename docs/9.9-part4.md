# 9.9 第四部分：完成 Armor 网络检测入口并复查前三部分

本轮完成第四部分。第三部分已提前增加语义构造和必要初值，本轮将其改为独立实现，删除无业务调用的旧网络构造，并复查前三部分的数据链。改动区域标记为 `[9.9-4]`。

## 修改、原因和效果

| 文件 | 修改 | 原因和效果 |
| --- | --- | --- |
| `tasks/auto_aim/armor.hpp/.cpp` | 网络构造只保留 `Color / ArmorName / ArmorType / double confidence / bbox / 四角点 / image_size` 语义入口 | 模型标签映射统一交给 Decoder，Armor 不再猜测裸 ID 的含义 |

| 同上 | 独立初始化，使用 `std::move` 接管传入的角点 vector | 去掉第三部分借用旧构造的临时过渡，避免其中多余的角点容器复制；保持 double 置信度 |
| 同上 | 校验尺寸、点数、语义、置信度、边界、bbox 包络、凸性和绕向 | 即使其他调用方绕过 Decoder，也不能把共线、自交、凹四边形或错误包围框交给这个网络入口 |
| 同上 | 保持已有标量初值，显式标明 OpenCV 点、矩形和默认灯条状态 | priority、duplicated、class_id、center_norm、位姿等状态确定；网络结果可安全复制 |
| `tasks/auto_aim/hailo/hailo_decoder.cpp` | 生成整数 bbox 时直接对实际角点最大值向上取整 | 修复 FLOAT32 的 `min + (max - min)` 舍入导致包围框漏包亚像素角点的问题；不夹紧或移动 PnP 角点 |
| `tests/armor_constructor_test.cpp`、`tests/hailo_decoder_test.cpp`、独立测试 CMake | 增加直接构造测试、旧入口编译期检查、混合精度融合到 Armor 的回归和亚像素 bbox 回归 | 同时验证第四部分和第二、三部分的接口衔接，不依赖实际设备 |
| 根/auto_aim CMake、README | 更新阶段状态 | 区分已经完成的 Armor 网络入口与仍待接入的 YOLO 图像入口 |

SP25 的网络几何公式（中心、ratio、rectangular_error）保持原定义。传统 Lightbar 和传统 Armor 构造的几何实现保留。没有改动 Tracker、Solver、Target、Aimer、Shooter、Voter、Planner、IO 或标定算法，也没有开始第五部分的相机改造。

## 本次确认并处理的问题

1. **直接构造 Armor 仍能接受退化四边形。** 新增入口测试在修复前实际失败：`FAIL: Accepted collinear points`。第三部分的 Decoder 会过滤此类候选，但公共 Armor 构造此前只检查点数、范围和边长，不能独立保证非退化几何。本轮在几何计算之前补齐校验，错误输入抛出 `std::invalid_argument`。
2. **语义入口仍依赖已过时的 class_id 构造。** 本轮将原网络几何公式集中到语义入口，并移除四套旧入口及无调用的类别表，消除重复实现。
3. **第三部分的 bbox 可能因为浮点舍入漏包角点。** 可复现数值为最小坐标 `0.3075F`、最大坐标 `nextafter(3.0F, 4.0F)`：以 FLOAT32 重算 `min + width` 会变为 `3`，旧方式得到的右边界是 3，而真实角点略大于 3。本轮直接取真实最大角点，正确得到边界 4，并保留原角点。

网络构造要求四个点已经按 LT/RT/RB/LB 排列；检查凸性和绕向不会自动证明模型给出的点身份正确。bbox 作为几何包络允许右/下角点等于 `x+width` / `y+height`，不会误用 OpenCV 半开区间 `contains` 拒绝边界点。

`class_id` 字段保留为 -1 以兼容 SP25 数据结构，不再生成旧网络类别号。默认 `priority=fifth` 是确定初值，不是新增的兵种优先级策略。零位姿表示尚未由 Solver 解算，不代表已测得有效位置。

## 验证方式

不需要模型或 NPU 的独立测试入口现在有三项：

```text
hailo_output_contract
hailo_decoder_contract
armor_constructor_contract
```

第三项覆盖：四种颜色 × 八种有效编号 × 两种大小枚举透传，原 SP25 不对称梯形几何结果，默认成员，坏点数/NaN/Inf/共线/自交/凹四边形/反向点序，bbox 包络和整数边界，角点所有权及传统灯条几何。编译期检查四套旧网络构造不再可调用。

Linux 下在工程根目录复现：

```bash
cmake -S tests/hailo -B build/hailo-tests -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_CXX_FLAGS='-Wall -Wextra -Wpedantic -fsanitize=address,undefined -fno-omit-frame-pointer' \
  -DCMAKE_EXE_LINKER_FLAGS='-fsanitize=address,undefined'
cmake --build build/hailo-tests -j2
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build/hailo-tests --output-on-failure
```

本轮 Windows/WSL 的挂载目录遇到 CMake 临时可执行文件删除权限问题，因此实际使用 WSL 原生 `/tmp/sp25-part4-*` 目录构建，源文件仍留在工程内。完整验证脚本保留在 `build/part4-validation/check_linux.sh`，实际测试结果和清理情况记录在同目录的 `results.md`。

本轮最终结果：

- WSL Ubuntu 22.04 / GCC 11.4 / OpenCV 4.5.4 下，开启 `-Wall -Wextra -Wpedantic` 的独立构建通过，无编译警告。
- 启用地址、未定义行为和泄漏检查，CTest **3/3 通过**，总测试时间 1.52 s，不作为性能指标。
- 11 个上层和业务消费者源码的编译兼容检查通过。
- standard、standard_mpc、uav 三个入口因缺少 `nlohmann/json.hpp` 停止；根 CMake 配置因缺少 nlohmann_json 开发包配置停止。这是已有环境依赖问题，完整链接没有通过验收。JSON 仍被 Plotter 和多个业务/测试代码使用，因此保留依赖。
- HailoRuntime/HailoOutput、上层算法、IO、标定、配置文件与本轮基线哈希一致；传统 Lightbar/Armor 的几何实现文本保留。
- 已删除最终 WSL 构建目录 23,488,961 字节的文件，以及 Windows 失败配置目录 157,097 字节；验证目录只保留小型脚本和结果记录。

验证脚本会分别报告测试与各源码检查；若主程序仍缺上述依赖，最终返回非零，不会把受阻的完整工程误报为通过。

## 上板仍需确认的内容

第四部分是 **Armor 数据对象的网络入口**，不是将整个 YOLO、相机或自瞄主程序接通。本轮没有恢复完整检测程序的构建。

- 第二部分仍需 HailoRT 4.23.0 的实际链接、HEF 加载及连续推理验证。
- 第三部分目前仅接受已经还原为输入像素的角点、整图直接 resize；如果实际 HEF 输出 raw grid/anchor 编码，须根据同一份模型的源码补齐转换。
- 模型类别顺序、角点身份、sigmoid、RGB/归一化语义及 YOLO 前处理接入仍待真实资料核对。
- 70–80 FPS、实际识别精度和长稳只能在目标 Pi 完整链路上验收，本轮离线测试不能替代。

## 2. 修改与作用

所有变更按组标记 `[Pi方向]`，继续使用原 SP25 相机、帧池、YOLO 和预览：

| 文件 | 修改 | 作用 |
| --- | --- | --- |
| `io/hikrobot/hikrobot.hpp` | `HikRobotOptions` 新增 `rotate_180`，默认 false | 原配置不带该字段时保持原行为；方向由配置明确决定 |
| `io/hikrobot/hikrobot.cpp` | 读取该字段；BGR 转换完成并归还 SDK 缓冲后，对未发布的独占槽位执行 `cv::flip(image, image, -1)` | 等价于旋转 180 度；所有消费者共用修正后的像素，不修改已经交付的帧 |
| 同一驱动 | 启动日志增加 `rotate_180=... (software)` | 在 Pi 日志中确认运行的是新程序及方向配置 |
| `configs/camera.yaml` | 设置 `rotate_180: true`，注明实测待核对和标定方向要求 | 对当前这一路海康图像启用修正，曝光/增益/触发/抽取/分辨率保持不变 |
| `tests/hikrobot_driver_test.cpp` | 非均匀像素测试、配置开关/非法值检查、两种输入格式与重连覆盖 | 防止把 180 度旋转写成单轴镜像、改变 BGR 通道或破坏帧引用 |

保留 720×540 输出，像素位置从 `(x,y)` 对应到 `(width-1-x,height-1-y)`。sequence、设备帧号、主机收帧时间戳语义不变；旋转耗时自然进入后续读取图像时的主机帧龄。没有额外保留图像队列或要求调用新 SDK 配置节点，原 TriggerSelector/抽取枚举修复仍保留。

这次仅修方向；曝光仍 3 ms、gain 10，检测置信度 0.8、NMS 0.5。方向修正不保证亮度或识别效果立即合格，后续根据新图判断，不同时调多个参数。

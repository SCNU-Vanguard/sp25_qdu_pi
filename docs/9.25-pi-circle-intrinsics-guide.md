# 树莓派圆点板相机内参标定（SSH + 浏览器）

本阶段只测当前相机和镜头的 `camera_matrix`、`distort_coeffs`。不需要 C 板、IMU、Hailo 推理或云台运动。相机内参标定不等于手眼/云台/IMU 坐标系标定；后者单独进行。

## 先确认板型，不要直接采用仓库默认尺寸

用户现场板的规格尚待确认。当前程序支持黑点白底、上下对齐的**对称圆点阵列**。若是错列圆点、白点黑底或带特殊标记的板，先提供板型信息，再确定处理方式。

在 `configs/calibration.yaml` 中只设置以下三个参数，按实物填写：

- `pattern_cols`：每行圆点个数；不是圆点之间的格子数。
- `pattern_rows`：圆点行数。
- `center_distance_mm`：同一行相邻两个圆心之间的距离，单位毫米；不是圆点直径，也不是两圆边缘间隙。

原文件的 10 列、7 行、40 mm 是历史默认值，尚未确认适用于用户的板。新入口遇到 `pattern_asymmetric: true` 会拒绝运行，防止把错列板当成矩形阵列计算。

修改前检查 Git 状态，板型参数、正式标定结果各自保留提交。原图和计算中间文件放在 `build/`，不加入 Git；重要原始采集数据另外备份，清理 build 前必须保留它们。

## 固定成最终相机设置

采集读取 `configs/pi_standard3_qdu.yaml` 的相机配置，与自瞄保持一致：DA6589759、720×540、2×2 抽取、软件旋转 180°。其他自瞄配置项不参与采集。

1. 相机固定，镜头先对焦到实际使用距离，调好后锁紧。
2. 标定期间和后续使用不要改变焦距、对焦、抽取、裁剪、图像旋转或输出尺寸。
3. 相机不动，移动标定板。使用平整硬板，保持全部圆点和周边白边在画面内。
4. 均匀照明，避开反光、阴影和运动模糊。必要时改善照明；曝光/增益调整与焦距改变不是一回事，但每张图必须清晰。
5. 停止 `standard_readonly`、相机测试等占用相机的程序。模拟器也不需要运行。

## 工具与原有程序的区别

- `calibration/capture_intrinsics.cpp` → `capture_intrinsics`：只打开 Camera；浏览器显示圆点连线；检测到完整圆点阵列时定时保存无框 PNG。
- `calibration/calibrate_intrinsics.cpp` → `calibrate_intrinsics`：离线读原图，检测圆点、计算内参和畸变，输出每张图的误差和复核图。不弹窗，不连接设备，不改正式配置。
- `calibration/circle_grid.hpp`：两个入口共用板型读取和圆点检测，避免采集/计算使用不同板型。
- 原有 `capture`、`calibrate_camera` 保持不变。它们使用本地图形窗口，旧 capture 还打开 CBoard；此次不要使用它们。

## 编译（代码同步完成后，在树莓派执行）

```bash
cd ~/sp_vision_25-main
cmake -S . -B build/pi-standard &&
cmake --build build/pi-standard --target capture_intrinsics calibrate_intrinsics -j4
```

## 采集（板型确认并写入配置后执行）

一个 SSH 窗口即可。电脑浏览器通过树莓派 IP 查看画面，树莓派不需要接显示屏。

```bash
./build/pi-standard/capture_intrinsics configs/pi_standard3_qdu.yaml \
  --pattern-config=configs/calibration.yaml \
  --output-folder=build/calibration/20260925-run01 \
  --preview-port=8080 --interval=5 --max-samples=30 --seconds=600
```

在电脑浏览器打开 `http://树莓派实际IP:8080`。输出目录必须是新的；重拍用 `run02` 等，不覆盖原始数据。

- `grid=OK`：本帧找齐了圆点。
- `saved=8/30`：已保存 8 张。
- `next=2.0s`：下一次允许保存还剩约 2 秒；到时也必须找齐圆点才保存。
- 图上彩色连线只用于检查；磁盘 `0001.png` 等是未画线的原图。不要使用网页截图或浏览器 JPEG 来标定。
- 每次保存后换姿势，接近倒计时结束时拿稳。若没有检测到，计数不会增长，先看姿势/照明/板型，不要继续收集大量重复图。
- 默认满 30 张或达到 10 分钟停止；Ctrl+C 可以提前停止并保留已拍图片。

建议 30 张分配（以实际识别情况调整）：

| 组 | 建议张数 | 摆放 |
|---|---:|---|
| 不同位置 | 10 | 中间、左右、上下、靠近四角，全部圆点仍在画面内 |
| 不同倾斜 | 12 | 中等程度左右转、前后倾、少量画面内旋转；避免全部正对镜头或倾斜到圆点挤成一条 |
| 不同距离 | 8 | 在合理工作距离内改变板在画面中的大小，兼顾清晰度与覆盖范围 |

仅平移同一个正面姿势、只在正中央反复拍、几十张几乎相同的照片，都不足以保证标定质量。内参采集不要求相机或标定板位于“世界原点”。

## 计算与复核

```bash
./build/pi-standard/calibrate_intrinsics build/calibration/20260925-run01
```

默认使用采集目录的 `pattern-used.yaml` 快照，不会因随后修改板型配置而意外改变本批计算。

结果：

- `build/calibration/20260925-run01/intrinsics.yaml`：尺寸、板型、有效张数、总体 RMS、平均点误差、两组参数及每张图 RMS。
- `build/calibration/20260925-run01/review/*.png`：每张原图的圆点识别复核图。
- `camera-used.yaml`、`pattern-used.yaml`：采集时配置快照。
- `frames.csv`：原图文件名、相机帧号和尺寸。

最少要求 20 张识别成功的视图。图片编号缺号不会截断读取；尺寸混用、空数据、结果路径已存在会拒绝继续。

使用现有 SP25 五系数模型，固定 k3=0。`rms_px` 与 `mean_point_error_px` 是不同统计量，不要混用。低 RMS 只说明这些观测拟合得好，不能单独证明标定正确。助手还应检查：

1. 圆点是否完整正确排序，图像是否清晰；
2. 位置、倾斜角度和距离是否有足够变化；
3. 内参数值是否合理，是否存在明显高误差图；
4. 留出未参与标定的图或独立测量，检查重投影和实际距离。

不要仅为了降低总体误差就大量删除边缘或倾斜照片；先查图像和检测错误。如果要重新计算，使用新的 `--output-file` 和 `--review-folder`，保留上一次结果。

## 最终填哪里

验收结果后，将 `intrinsics.yaml` 中完整的这两项复制到**实际自瞄运行配置** `configs/pi_standard3_qdu.yaml`，替换原来的同名值，不要重复追加键：

```yaml
camera_matrix: [fx, 0, cx, 0, fy, cy, 0, 0, 1]
distort_coeffs: [k1, k2, p1, p2, k3]
```

上面是字段含义，不是可运行数值。使用工具输出的实际数字，保持顺序。

不要把这次结果填入或覆盖 `R_camera2gimbal`、`t_camera2gimbal`、`R_gimbal2imubody`。本次也不调整 `yaw_offset` / `pitch_offset`。那些属于后续安装关系、坐标系和瞄准偏置核准。

对已经旋转后的 720×540 原图标定，结果已经对应最终图像，不要再额外旋转内参或乘除分辨率。保存 Git 提交，再重跑单装甲板几何检查和只读跟踪；内参正确不代表手眼关系已正确。

## 本次开发验证与限制

- WSL Ubuntu 22.04、OpenCV 4.5.4：离线入口真实编译；采集入口真实源码搭配测试专用文件相机编译运行。
- 24 张已知内参的合成圆点图，均识别成功；恢复焦距误差在 5% 容限内，RMS 约 0.0314 px（仅合成数据，不是实机标定精度）。
- 自动测试验证：无 DISPLAY、编号缺号、排除非原图、尺寸混用/样本不足拒绝、禁止覆盖结果。
- 采集测试验证：浏览器页面可访问、保存图像与原图逐像素一致、保留配置与帧号、重复目录拒绝。
- 未在用户树莓派上编译运行新入口；真实海康采集、现场板型与真实标定质量仍待现场验证。

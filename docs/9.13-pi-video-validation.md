## 2. 计时怎么理解

| 输出 | 含义 |
| --- | --- |
| `processed_frames` | 正式顺序读帧并完成检测的帧数，不含额外预热 |
| `video_detector_fps` | 帧数 ÷ 全部 `YOLO::detect` 调用时间之和；含缩放/RGB、推理、反量化、tail、Decoder/NMS、Armor |
| `video_read_detect_fps` | 帧数 ÷ 整个读取循环墙钟时间；含读盘/解码、检测、轻量统计、结果析构和末次读到结束 |
| `detect_ms` | 每次 `detect` 的平均、p95 上界和最大耗时 |
| `read_detect_ms` | 每次成功读取开始到本帧检测结束的平均、p95 上界和最大耗时；含输入格式检查，不含随后统计/析构和末次失败读取 |
| `empty_detection_frames` / `multi_detection_frames` | 检出 0 个 / 超过 1 个装甲的帧数；不是人工标注的无目标/多目标数量 |

使用单调时钟 `steady_clock`。平均值和最大值统计全部成功帧；p95 使用固定直方图，桶宽 **0.05 ms**，报告所在桶的上边界，最多比该分位点高约 0.05 ms。超过 1000 ms 进入溢出桶；如果 p95 也超出，会输出 `>1000`，最大值仍保留真实值。两组直方图合计约 313 KiB，不随视频长度增长；只保留当前帧和当前结果，不积攒整段历史。

初始化、首次预读、10 次预热和重新打开视频不计入基线。两个 FPS 都不含相机、跟踪、解算、瞄准及通信。若检测本身快而含读帧的吞吐慢，应先看录像解码开销，不能把后一个数字直接叫 NPU FPS，也不能用它替代真实相机联合实测。

### 7.2 生成与回收命令

启动终端：电脑提示符形如 `PS D:\workspace\sp_vision_25-main>`，属于 PowerShell。在这里用 `ssh xiao@192.168.1.105` 连接 Pi；`ssh` 启动远程终端，`xiao` 是 Pi 用户名，`192.168.1.105` 是当前使用的 Pi 地址。连接后提示符形如 `xiao@PI-HAILO-13T:~ $`，属于 Pi Bash，`~` 表示 `/home/xiao`。已有该 Pi 提示符时无需再次 SSH；复制命令时不包含提示符本身。`exit` 是结束 SSH 返回电脑，不是启动检测。

下面的 `task_sp25='/home/xiao/sp_vision_25-main'` 只设置一个 Bash 变量，表示工程所在目录；等号两侧不能有空格。`$task_sp25` 表示取变量值，双引号内也会替换；赋值本身不会启动程序。完整路径不依赖当前目录，所以即使提示符仍在 `~` 也能运行。变量仅用于当前终端会话，重新连接后要重新赋值。

以 `"$task_sp25/build/pi-hailo/hailo_detector_video_test"` 开头的命令才是运行已编译程序；`build/pi-hailo` 是构建目录，末尾名称是可执行文件，Linux 可执行文件通常不以 `.exe` 结尾。此前 `cmake --build` 负责生成这个文件，现在直接执行它，不再编译。输入参数依次为检测 YAML、视频文件、`--expect-frames 687` 和抽查选项。

`configs/pi_hailo.yaml` 提供模型 HEF 路径、模型类型、阈值等；`assets/demo/demo.avi` 是输入视频。`--expect-frames 687` 表示结束后核对处理数量，不是限制到第 687 帧就停止，也不是指定 FPS。`--samples 输出目录 下标列表` 切换到结果抽查模式，仍检测整个视频，只额外保存指定帧，不输出速度基准。下标从 0 开始，`0,100,400,500,600,686` 对应顺序第 1、101、401、501、601、687 帧。

若对话先设置 `task_samples="$task_sp25/build/pi-hailo/video-samples-A1"`，它只是给输出目录取一个变量名；传入 `--samples "$task_samples"` 与下面直接填写完整目录相同。输出目录由程序自动创建且必须原先不存在。成功后其中有 6 张 `frame-N-raw.png` 原图、6 张 `frame-N-result.png` 标注图和 `samples.txt` 记录；不保存完整输出视频。

命令行末尾的 `\` 是 Bash 续行符，表示下一行仍属于同一个命令，后面不要有空格。逐行输入时提示符出现 `>` 表示 Bash 还在等待剩余命令，不是错误；最后一行不带 `\`，回车后才启动。整块粘贴时变量赋值、程序运行和后续 `echo` 会顺序执行。

启动后程序读取首帧、初始化一次 YOLO/Hailo 模型、预热 10 次，再重新打开视频从第 0 帧逐帧推理，并保存选中的结果。它在终端前台运行，不弹出视频窗口，处理中没有逐帧进度打印，保存图片需要额外时间。正常跑完后终端提示符重新出现，随后 `echo "exit_code=$?"` 显示刚结束程序的返回码；`$?` 必须紧接程序查看，先执行其它命令会改变它。0 表示程序报告正常完成，非零需要检查输出。需要中断时按 Ctrl+C，中断的运行不作为完整验收，已经生成的部分文件会保留。

下面 `Set-Location` 进入电脑工程目录；`$task_remote = ...` 保存 Pi 远端路径的前半段，`+=` 将子目录追加到同一个字符串。冒号前是 Pi 用户和地址，冒号后是该用户主目录下的路径。`scp -r` 才开始传输：`-r` 表示复制整个目录，第一个参数是 Pi 上的来源，第二个参数是电脑上的接收目录；`./`（PowerShell 中常写为 `.\`）表示当前目录。程序运行已结束，这一步只复制现有文件。

```powershell
Set-Location D:\workspace\sp_vision_25-main
$task_remote = 'xiao@192.168.1.105:sp_vision_25-main/'
$task_remote += 'build/pi-hailo/video-samples-A1'
scp -r $task_remote .\build\pi-video-validation\
```

如提示密码，输入 Pi 用户 `xiao` 的登录密码并回车，终端不显示输入字符。传输时会显示文件名和进度，结束后返回 `PS ...>` 提示符；紧接着在 PowerShell 执行 `Write-Output "scp_exit_code=$LASTEXITCODE"` 可查看 scp 返回码。这里使用 PowerShell 的 `$LASTEXITCODE`，不是 Bash 中的 `$?`。成功回收的目录为 `D:\workspace\sp_vision_25-main\build\pi-video-validation\video-samples-A1`。用户报告传输结果后，由助手直接读取本机文件，核对数量和实际图像内容。
